拦截处理、错误诊断与额度

2026-10-20。只记录可支持的结论，不以反复试错消耗额度。

已发生的情况

T24曾有输入拦截，后续独立且充分着装的儿童雨衣场景成功；T28两次输出拦截后没有可用成图。它们不能证明某个词必定触发，也不能证明减少几个词就能通过。保留原错误、请求ID、阶段与当时引用的图，避免脱离上下文归因。

GitHub一手案例怎样借鉴

  • OpenAI Python SDK：错误处理：区分输入错误、限额、连接和服务端问题；需要诊断时保留request ID。只存摘要，不在公开日志放隐私图片或凭证。
  • OpenAI 图像生成官方说明：根据返回的实际错误类别判断。当前内置工具没有暴露API的所有参数，不能拿API文档里的选项当成本工具已有开关。
  • 不制作绕过、关闭、编码隐藏或拆分组合安全限制的方案。对误判可保留证据反馈；对实际不合适的内容改正内容本身，并停止原样重试。

生成前的实际改进

明确成人角色与适合场景的动作。儿童场景仅使用独立的儿童设定和充分着装的参考，不混入成人泳装、成人体态或亲密姿势图。减少互相冲突和无关的参考图。家居就用家居服装参考，不让旧图中的服装、姿势和场景互相污染。这是减少歧义，不是通过审核的保证。

内容拦截不自动重试。网络故障、限流或服务端错误分别记录，按工具说明处理；不把安全拦截当成网络故障循环调用。

额度

当前能核实的是保存了35个作品编号、48张含修改版图片。这个数字不是剩余额度，也无法推出剩余2张或每日50张。图像工具没有提供本账户余额查询接口；以产品当时显示的额度或重置提示为准。

下一轮规划20张，本轮实际生成0张。先3张，每张看完后再继续；不自动大批重抽。失败不凭猜测计费，在记录里标未知。
